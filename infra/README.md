# Cloud deployment (Google Cloud)

Everything runs in one GCP project in **`europe-west1`** (Belgium). It's one of the few EU
regions that has Cloud Run, Cloud SQL **and** API Gateway, and it's in Cloud Run's cheaper
price tier 1.

```
agent (local CLI) ──REST──▶ API Gateway ──ID token──▶ Cloud Run billing-api ──socket──▶ Cloud SQL (PG 16)
        │                (JWT check: JWKS             (requires auth: only the
        │                 served through the gateway)  gateway's service account may invoke)
        └──MCP (X-API-Key)──▶ Cloud Run mcp-server (public; not behind the gateway)
```

| Resource          | Name                                               | Notes                                                                                                                                                                                           |
| ----------------- | -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Artifact Registry | `billwise` (docker)                                | images `billing-api`, `mcp-server` (linux/amd64)                                                                                                                                                |
| Cloud SQL         | `billwise-pg`                                      | PostgreSQL 16, Enterprise `db-f1-micro`, 10 GB HDD, zonal, no backups. Public IP with **no authorized networks** + connector enforcement: only Cloud SQL connectors with IAM access can connect |
| Secret Manager    | `DATABASE_URL`, `JWT_PRIVATE_KEY`, `MCP_API_KEY`   | generated by `deploy.sh`, never printed; mounted as env vars                                                                                                                                    |
| Service accounts  | `billing-api-run`, `mcp-server-run`, `api-gateway` | least privilege (see `step_iam`)                                                                                                                                                                |
| Cloud Run         | `billing-api`                                      | `--no-allow-unauthenticated`; `roles/run.invoker` only for `api-gateway`                                                                                                                        |
| Cloud Run         | `mcp-server`                                       | public, every request needs `X-API-Key`                                                                                                                                                         |
| API Gateway       | API `billwise-api`, gateway `billwise-gw`          | config: [`gateway/openapi-gateway.tmpl.yaml`](gateway/openapi-gateway.tmpl.yaml) (OpenAPI 2.0)                                                                                                  |

## Gateway routes

All paths are versioned under `/api/v1` (plus the standard JWKS path).

| Route                                                                                            | Gateway auth       | API auth      |
| ------------------------------------------------------------------------------------------------ | ------------------ | ------------- |
| `POST /api/v1/auth/login`                                                                        | –                  | –             |
| `GET /api/v1/bills/{subscriberNo}`                                                               | – (public by spec) | –             |
| `GET /api/v1/health`, `/api/v1/health/ready`                                                     | –                  | –             |
| `GET /.well-known/jwks.json`                                                                     | –                  | –             |
| `GET /api/v1/docs` (→ `/api/v1/docs/index.html`), `/api/v1/docs/{asset}`, `/api/v1/openapi.json` | – (Swagger UI)     | –             |
| `GET /api/v1/bills/{subscriberNo}/detailed`                                                      | JWT                | self or ADMIN |
| `POST /api/v1/payments`                                                                          | JWT                | self or ADMIN |
| `POST /api/v1/usage`                                                                             | JWT                | ADMIN         |
| `POST /api/v1/bills/calculate`                                                                   | JWT                | ADMIN         |

- **JWT check at the gateway:** the gateway checks the RS256 signature, `iss = billwise-billing-api` and `aud = billwise-api` against `https://<gateway-host>/.well-known/jwks.json`, so the public keys are also fetched through the gateway.
- **Headers to the backend:** the gateway calls Cloud Run with its own ID token and forwards the user's token as `X-Forwarded-Authorization`, which the API reads first.
- **Example error:** without a token the gateway answers itself (see [`gateway-401-example.json`](gateway-401-example.json)).
- A unit test (`packages/billing-api/src/routes/gateway-config.test.ts`) keeps the gateway config in sync with the implemented routes.

## Prerequisites

- **Tools:**
  - `gcloud` (logged in as a project Owner: `gcloud auth login`)
  - Docker (builds `linux/amd64`)
  - Node.js ≥ 22, `npm ci` done at the repo root
  - bash. On Windows use Git Bash and point `GCLOUD` at `gcloud.cmd` by its **8.3 short path**,
    e.g. `GCLOUD='C:\Users\<you>\AppData\Local\Google\CLOUDS~1\google-cloud-sdk\bin\gcloud.cmd'`
    (find it with `dir /x` in `%LOCALAPPDATA%\Google`). `gcloud.cmd` under `Cloud SDK` (with a
    space) fails as soon as an argument contains a space: cmd.exe strips its quotes.
    For `docker push`, also put the SDK `bin` folder on `PATH`: Docker Desktop calls
    `docker-credential-gcloud` from there.
- **Cloud SQL Auth Proxy:** `gcloud components install cloud-sql-proxy`, or set `PROXY_BIN=/path/to/cloud-sql-proxy`.
- **Seed passwords:** `.env` with `SEED_ADMIN_PASSWORD` / `SEED_USER_PASSWORD`. The cloud seed uses the same demo passwords as the README.
- **No service account keys:** none are needed, and the org policy `iam.disableServiceAccountKeyCreation` forbids them anyway. Locally everything uses your gcloud login (`--gcloud-auth` for the proxy). In the cloud, services run as their attached service accounts.

## Deploy

```bash
# Preview any step without changing anything:
DRY_RUN=1 infra/deploy.sh apis

infra/deploy.sh apis registry images     # APIs, Artifact Registry, build + push images
infra/deploy.sh sql secrets iam          # Cloud SQL, secrets (generated), service accounts + roles
infra/deploy.sh db-init                  # migrate + seed through the Auth Proxy (from your machine)
infra/deploy.sh run gateway              # Cloud Run services, API Gateway (2 passes: JWKS via its own host)
infra/deploy.sh env-cloud verify         # .env.cloud for the agent, security checks
# or: infra/deploy.sh all
```

Override settings with env vars, e.g. `PROJECT_ID=my-project REGION=europe-west1 infra/deploy.sh all`.

**Re-running steps:**

- Re-runs are safe. Existing resources are kept, and **secrets are never rotated** by a re-run.
- `images` + `run` deploys a new revision.
- `gateway` uploads a new immutable api-config and switches the gateway to it.

`infra/deploy.sh status` / `infra/deploy.sh urls` are read-only.

## Run the agent against the cloud

```bash
infra/deploy.sh env-cloud        # writes .env.cloud (gitignored): gateway URL, cloud MCP URL + key, proxy DB URL
npm run chat:cloud               # chat: REST through the gateway, docs through the cloud MCP server
npm run demo:cloud               # scripted demo against the cloud (does NOT re-seed by default)

# Re-seed Cloud SQL before the demo: start the proxy in a second terminal first
cloud-sql-proxy --gcloud-auth --port 5433 project-b81d9425-6ed1-4fb6-a4e:europe-west1:billwise-pg
npm run demo:cloud -- --reseed
```

- **How `.env.cloud` is loaded:** `--cloud` (or `ENV_FILE=<file>`) loads `.env.cloud` **first**, so its values win. `.env` still supplies everything else (`GEMINI_API_KEY`, seed passwords).
- **Local setup:** plain `npm run chat` / `npm run demo` still use the local stack only.
- See [`.env.cloud.example`](../.env.cloud.example).

## Verify

`infra/deploy.sh verify` checks:

- **Direct Cloud Run call** to billing-api without an identity token → **403**, so the gateway can't be bypassed.
- **Gateway `POST /api/v1/payments` without a token** → **401**. The body is saved to `infra/gateway-401-example.json`.
- **Gateway login, then `GET …/detailed` with the token** → **200**. Through the gateway the plain `Authorization` header carries Google's token, so a 200 proves the API used `X-Forwarded-Authorization`. The structured Cloud Logging entry (`jsonPayload.auth = "x-forwarded-authorization"`) is shown too.
- **Tampered token** → **401**.
- **Swagger UI** (`/api/v1/docs/index.html` and its assets) and the JWKS → **200** through the gateway.

## Stop / start

```bash
P=project-b81d9425-6ed1-4fb6-a4e
# Stop (Cloud Run then answers /health/ready with 503):
gcloud sql instances patch billwise-pg --activation-policy=NEVER --project=$P
# Start again (takes ~1–2 min):
gcloud sql instances patch billwise-pg --activation-policy=ALWAYS --project=$P
```

⚠️ **Stopping saves almost nothing here.** A stopped instance still pays for its storage ($0.90),
and its reserved public IPv4 is billed while it is stopped ("Zonal - IP address reservation in EMEA",
**$0.01 / h ≈ $7.30 / month**). That makes stopped ≈ $8.2 a month versus ≈ $8.6 running. Stopping is
useful to make the API unreachable, not to save money. To really stop paying, **delete the Cloud SQL
instance** (see Teardown) and recreate it with `infra/deploy.sh sql secrets db-init` when needed.

Cloud Run, API Gateway, Artifact Registry and Secret Manager cost nothing while idle, so they can stay.

## Before making the repository public

The cloud seed uses the **same demo passwords as the README**, and those accounts are reachable
through the public gateway. Before the repository (or the README with the gateway URL) goes public,
do **one** of these:

1. **Shut the cloud stack down** (see Teardown, or at least stop Cloud SQL), **or**
2. **Rotate the credentials:**
   - Re-seed with new `SEED_ADMIN_PASSWORD` / `SEED_USER_PASSWORD` values that are not in the repo.
   - Rotate the JWT signing key (`gcloud secrets versions add JWT_PRIVATE_KEY --data-file=-` with a new PEM, then `infra/deploy.sh run` to roll a new revision). Every token issued so far becomes invalid.
   - Optionally rotate `MCP_API_KEY` the same way.

## Teardown (deletes everything; irreversible)

```bash
P=project-b81d9425-6ed1-4fb6-a4e; R=europe-west1
# 1. API Gateway (gateway → configs → API)
gcloud api-gateway gateways delete billwise-gw --location=$R --project=$P
for c in $(gcloud api-gateway api-configs list --api=billwise-api --project=$P --format='value(CONFIG_ID)'); do
  gcloud api-gateway api-configs delete "$c" --api=billwise-api --project=$P --quiet
done
gcloud api-gateway apis delete billwise-api --project=$P
# 2. Cloud Run
gcloud run services delete billing-api --region=$R --project=$P
gcloud run services delete mcp-server --region=$R --project=$P
# 3. Cloud SQL (deletion protection first; ALL DATA IS LOST)
gcloud sql instances patch billwise-pg --no-deletion-protection --project=$P
gcloud sql instances delete billwise-pg --project=$P
# 4. Secrets, images, service accounts
gcloud secrets delete DATABASE_URL --project=$P
gcloud secrets delete JWT_PRIVATE_KEY --project=$P
gcloud secrets delete MCP_API_KEY --project=$P
gcloud artifacts repositories delete billwise --location=$R --project=$P
for sa in billing-api-run mcp-server-run api-gateway; do
  gcloud iam service-accounts delete "$sa@$P.iam.gserviceaccount.com" --project=$P
done
gcloud projects remove-iam-policy-binding $P \
  --member="serviceAccount:billing-api-run@$P.iam.gserviceaccount.com" --role=roles/cloudsql.client --condition=None
# 5. Optional: shut down the whole project (stops all billing; restorable for 30 days)
# gcloud projects delete $P
```

The enabled APIs cost nothing and can stay. Also delete the local `.env.cloud`.
